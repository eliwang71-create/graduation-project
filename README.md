# 校园通勤车系统

基于 `C++ + MySQL + HTML/CSS/JavaScript + 高德地图` 的校园通勤车调度系统，面向高校早晚高峰通勤场景，围绕带硬时间窗的车辆路径问题（`VRPTW`）进行建模与求解。系统以蚁群算法作为核心优化方法，支持真实高德路网调度和模拟节点调度两种模式，可用于毕业设计中的系统实现、算法实验和答辩演示。

## 系统简介

校园通勤车系统主要解决高校通勤场景中的几个典型问题：

- 早晚高峰通勤需求集中，站点服务时段重叠明显
- 校园周边道路拥堵，固定线路与固定发车模式难以适应动态需求
- 人工经验调度难以同时兼顾准时率、车辆容量和运行成本

本系统以 `VRPTW` 为核心模型，在容量约束、硬时间窗约束、最早发车时间约束和终点站到校约束下，对站点、车辆和调度结果进行统一管理，并通过蚁群算法搜索可行且更优的车辆调度方案。

## 系统模块

当前系统可以分为 5 个核心模块：

### 1. 系统概览模块

用于展示系统背景、校园通勤痛点、系统目标和能力总览，帮助用户快速理解：

- 为什么要进行校园通勤车调度优化
- 本系统的研究对象是 `VRPTW`
- 蚁群算法在本系统中的作用

### 2. 站点管理模块

用于维护真实通勤站点和模拟站点信息。

主要功能：

- 真实站点的增删查改
- 地图点击或地点搜索新增站点
- 设置需求人数、服务时间、时间窗
- 设置终点站
- 模拟节点模式下的样例载入与节点配置

### 3. 车辆管理模块

用于维护通勤车辆的基础信息和调度约束。

主要功能：

- 车辆增删查改
- 车辆容量管理
- 最大运行时长设置
- 最早发车时间设置

### 4. 调度求解模块

这是系统的核心模块，负责将站点、车辆和距离矩阵转化为 `VRPTW` 实例，并调用蚁群算法进行求解。

主要功能：

- 读取真实站点与车辆数据
- 调用高德 Web 服务生成真实距离矩阵和时间矩阵
- 构建 `VRPTWInstance`
- 通过 `AcoVrptwSolver` 求解车辆路径
- 检查容量、时间窗、最早发车时间和终点站约束
- 生成最终调度结果

### 5. 调度结果展示模块

用于将算法结果以地图和时刻表的形式展示出来。

主要功能：

- 真实高德模式下展示真实道路路径
- 模拟节点模式下展示算法迭代和最终路径
- 展示车辆路线时刻表
- 展示收敛曲线
- 展示蚁群算法原理与数学公式

## 双模式说明

### 真实高德模式

真实高德模式面向系统实际调度流程：

- 站点和车辆来自数据库
- 通过高德 Web 服务获取真实道路距离与行驶时间
- 后端执行蚁群算法求解
- 调度结果写回 `schedule`
- 前端地图展示真实道路路径和车辆时刻表

### 模拟节点模式

模拟节点模式主要用于论文展示和算法实验：

- 不依赖数据库中的真实调度结果
- 使用前端配置的模拟站点和模拟车辆
- 仍然调用项目中真实的蚁群算法求解器
- 展示算法迭代状态、收敛曲线和最终路径结果

这两个模式共用同一套算法核心，但输入数据来源和展示目标不同。

## 技术栈

- 后端：`C++`
- 数据库：`MySQL`
- 前端：`HTML + CSS + JavaScript`
- 地图服务：`高德地图 JavaScript API`、`高德 Web 服务 API`
- 算法：`Ant Colony Optimization (ACO)` + `VRPTW`

## 项目结构

- `backend/`：后端 API、数据库读取、调度服务、结果写回
- `algorithm/`：VRPTW 建模与蚁群算法求解器
- `database/`：数据库脚本、表结构、迁移和测试数据
- `frontend/`：系统前端页面与地图展示逻辑
- `docs/`：需求分析、设计文档、论文辅助材料

## 当前核心能力

当前项目已经具备以下能力：

- 真实高德地图展示

- 基于蚁群算法的 `VRPTW` 调度求解
- 调度结果写回数据库
